Primary consumer: Codex. Read during every `poc`, `debug`, and `exploit` task.

This file covers the Foundry-specific bits that recur across all five challenges: `foundry.toml` setup, `vm.createSelectFork` aliases, cheatcodes, and the revert-selector table you need to decode failed traces.

## 1. foundry.toml — the canonical layout

Every `challenges/<ch>/` directory is its own Foundry project. The template looks like this (do not hand-roll — copy from `templates/` if unsure):

```toml
# challenges/<ch>/foundry.toml
[profile.default]
src          = "exploit"
test         = "poc"
out          = "out"
cache_path   = "cache"
libs         = ["lib"]
solc         = "0.8.23"
optimizer    = true
optimizer_runs = 200
fs_permissions = [{ access = "read-write", path = "." }]

[rpc_endpoints]
ch1 = "${RPC_CH1_URANIUM}"
ch2 = "${RPC_CH2_HARVEST}"
ch3 = "${RPC_CH3_FEIRARI}"
ch4 = "${RPC_CH4_SUPERFLUID}"
ch5 = "${RPC_CH5_SUPERFLUID_V2}"

[etherscan]
mainnet = { key = "${ETHERSCAN_API_KEY}", chain = 1 }
polygon = { key = "${ETHERSCAN_API_KEY}", chain = 137 }
bsc     = { key = "${ETHERSCAN_API_KEY}", chain = 56 }

[fuzz]
runs = 10
```

Why this matters:
- `[rpc_endpoints]` aliases — `vm.createSelectFork("ch1", block)` resolves via this table, so tests don't need hardcoded URLs and your PRIVATE_KEY never touches source.
- Etherscan block under a single V2 key — enables `forge verify-contract --chain polygon` if you ever deploy.
- `solc = "0.8.23"` matches Superfluid reference files. For ch1/ch2/ch3 you may need `0.7.6` or `0.6.12` for Uniswap V2 style interfaces — use `pragma solidity >=0.6.12 <0.9.0` in PoCs and let Foundry auto-pick.

### 1.1 Gas-limit discipline (mentor warning)

**Do NOT raise `block_gas_limit` artificially to make a PoC pass.** The mentor lecture (lecture_1 §20:21) is explicit on this: if a PoC only succeeds with `vm.fee(0)` + manual gas override, it will **not** broadcast against the live fork — the challenge RPC enforces the real block gas limit.

Diagnostic checklist when a PoC fails with `out of gas`:
1. Read `chain_info.json` recorded by recon — `gasLimit` is the real ceiling.
2. If the exploit needs more than ~70% of `gasLimit`, split across multiple transactions, not gas override.
3. If a loop iteration is too gas-heavy, reduce `N` (iter count) and binary-search optimum — do NOT raise the ceiling. `exploit_harvest.skill.md §Score optimization` shows the gradient method.
4. `forge test --gas-report` quantifies per-function gas so you can find the hot spot.

Related: when the real RPC is an archive node, the default `eth_call` gas cap may be lower than block limit. If a view call reverts with `gas required exceeds allowance`, split the view into smaller pieces instead of raising `--gas-limit` on the cast side.

### 1.2 Vyper / non-Solidity ABI surfaces

Curve (most pools), Vyper-generated bytecode does not export a standard Solidity ABI, but function selectors ARE stable. When writing a PoC that touches Curve:

- Write a **minimal Solidity interface** manually from the Vyper `.vy` source on Etherscan. Example (`StableSwap`):
  ```solidity
  interface ICurveStableSwap {
      function exchange(int128 i, int128 j, uint256 dx, uint256 min_dy) external returns (uint256);
      function get_dy(int128 i, int128 j, uint256 dx) external view returns (uint256);
      function coins(uint256 i) external view returns (address);
      function balances(uint256 i) external view returns (uint256);
      function add_liquidity(uint256[2] calldata amounts, uint256 min_mint_amount) external returns (uint256);
      function remove_liquidity_one_coin(uint256 _token_amount, int128 i, uint256 min_amount) external returns (uint256);
      function calc_withdraw_one_coin(uint256 _token_amount, int128 i) external view returns (uint256);
  }
  ```
- Note: `int128` for coin indices (not `uint`), fixed-size arrays (e.g. `uint256[2]`, `uint256[3]`) match the pool's coin count exactly. A 3-coin pool uses `uint256[3]`; passing wrong-size arrays reverts early.
- For yVault-style contracts (Yearn-like — which Harvest uses as an intermediary): their ABI is pure Solidity, but the underlying `calc_withdraw_one_coin` call chain ends at a Curve Vyper contract. Interface mismatch at that boundary is the #1 source of silent reverts.
- Mentor lecture (lecture_2 §11:29) confirms: don't copy-paste Vyper code; port by hand.

## 2. Fork cheatcodes — which to use when

```solidity
// Create AND switch active fork in one call. Use this for 99% of tests.
uint256 forkId = vm.createSelectFork("ch2", 11_128_633);

// Just create, don't switch. Use for multi-fork scenarios (rare for us).
uint256 forkId = vm.createFork("ch2", 11_128_633);
vm.selectFork(forkId);

// Without a block number, forks at the RPC's current block.
vm.createSelectFork("ch2");

// Rollback to a prior fork state inside a single test.
vm.rollFork(11_128_600);   // same fork, earlier block
vm.rollFork(forkId, 11_128_600);

// Address persistence across forks (for custom attacker contracts deployed in setUp).
MyAttacker a = new MyAttacker();
vm.makePersistent(address(a));
```

Best practice: do `vm.createSelectFork` in `setUp()` ONLY. Do not re-fork inside test functions — `forge test` caches forks across tests that share a block, and re-forking invalidates the cache and adds 10-60s of RPC latency per test.

## 3. Cheatcodes that actually matter for our exploits

| Cheatcode | Use |
|---|---|
| `vm.deal(addr, wei)` | Give an account native balance without a mint |
| `vm.prank(addr)` | Next call's `msg.sender` = `addr` |
| `vm.startPrank(addr)` / `vm.stopPrank()` | Multi-call prank |
| `vm.startBroadcast(pk)` / `vm.stopBroadcast()` | Use in `.s.sol` scripts to sign from your EOA (DO NOT use in `.t.sol`) |
| `vm.warp(timestamp)` | Set `block.timestamp` (useful for Harvest cooldowns if any) |
| `vm.roll(blockNumber)` | Set `block.number` |
| `vm.expectRevert()` or `vm.expectRevert(bytes4)` | Assert that the next call reverts with selector |
| `vm.expectCall(target, calldata)` | Assert a specific downstream call happens |
| `vm.recordLogs()` / `vm.getRecordedLogs()` | Capture emitted events in-test |
| `vm.label(addr, "Vault")` | Pretty trace names |
| `deal(IERC20(token), to, amount)` | `forge-std` helper to stuff an ERC20 balance |
| `vm.setCode(addr, code)` | Overwrite any address's runtime bytecode (dangerous cheat) |
| `vm.store(addr, slot, value)` | Directly set storage — useful to break invariants |
| `vm.load(addr, slot)` | Read storage without an interface |

PoC template (matches `reference/IDAUsage_t.sol` style):

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.23;

import "forge-std/Test.sol";

/// @title Attempt N
/// @notice Hypothesis: <one line>
contract AttemptN is Test {
    address constant ATTACKER  = 0xc943edb4bb4439d65b81f2f60bc698411e910b14;
    address constant VAULT     = 0x...;

    function setUp() public {
        vm.createSelectFork("ch2", 11_128_633);
        vm.label(VAULT,    "Vault");
        vm.label(ATTACKER, "Attacker");
    }

    function test_exploit() public {
        uint256 start = ATTACKER.balance;
        console.log("[start] attacker ETH:", start);

        vm.startPrank(ATTACKER);
        // ... exploit calls
        vm.stopPrank();

        uint256 end = ATTACKER.balance;
        console.log("[end]   attacker ETH:", end);
        assertGt(end, start, "native balance must increase");
    }
}
```

## 4. Running tests and capturing traces

```bash
# Standard test run — stdout + events
forge test --match-path challenges/ch2_harvest/poc/Attempt3.t.sol

# With call trace (what you want for debug)
forge test --match-path challenges/ch2_harvest/poc/Attempt3.t.sol -vvv

# With full state diffs (slow, for really stuck debugs)
forge test --match-path challenges/ch2_harvest/poc/Attempt3.t.sol -vvvv

# Capture to log for the brain
forge test --match-path challenges/ch2_harvest/poc/Attempt3.t.sol -vvv 2>&1 \
  | tee challenges/ch2_harvest/runs/attempt3.log

# Specific test function
forge test --match-test test_exploit -vvv

# Gas report
forge test --match-path ... --gas-report
```

Verbosity legend:
- `-v`: logs (`console.log`) only
- `-vv`: + assertion results
- `-vvv`: + call traces for failed tests
- `-vvvv`: + call traces for ALL tests + state changes
- `-vvvvv`: + setUp traces

For production exploits use `forge script`, never `forge test`:

```bash
forge script challenges/ch2_harvest/exploit/Run.s.sol \
  --rpc-url ch2 \
  --private-key $PRIVATE_KEY \
  --broadcast \
  --slow \
  -vvv 2>&1 | tee challenges/ch2_harvest/runs/exploit_$(date +%s).log
```

`--slow` sends transactions one at a time (waits for receipt between each). Useful when later txs depend on earlier state — which is most exploits.

Dry-run first (no `--broadcast`) and check `native balance delta` in the output before attaching `--broadcast`.

## 5. Revert selector table — decoding failed traces

When a trace ends with `[Revert] 0x<4bytes><abi-encoded-args>`, the first 4 bytes tell you what reverted. Memorize these — they're the overwhelming majority of reverts you'll see.

| Selector | Decoded | Meaning |
|---|---|---|
| `0x08c379a0` | `Error(string)` | Human-readable `require(..., "message")`. Decode args as `string`. |
| `0x4e487b71` | `Panic(uint256)` | Solidity built-in panic. Sub-code in the uint256. |
| (empty) | — | Out of gas / raw `revert()` / assembly `revert(0,0)` with no data |
| `0xd92e233d` | `ZeroAddress()` | OpenZeppelin's generic null-address guard |
| `0xe450d38c` | `ERC20InsufficientBalance(address,uint256,uint256)` | OZ v5 ERC20 |
| `0xfb8f41b2` | `ERC20InsufficientAllowance(address,uint256,uint256)` | OZ v5 ERC20 |
| `0x82b42900` | `Unauthorized()` | Solady Owned |
| `0xd93c0665` | `NotOwner()` | generic |

Panic sub-codes (the uint256 argument to `Panic`):

| Code | Meaning |
|---|---|
| `0x01` | `assert(false)` hit |
| `0x11` | Arithmetic over/underflow (checked math) |
| `0x12` | Division by zero / modulo zero |
| `0x21` | Enum value out of range |
| `0x22` | Incorrectly encoded storage byte array |
| `0x31` | `.pop()` on empty array |
| `0x32` | Array/bytesN out-of-bounds |
| `0x41` | Too much memory allocated, or resize past limit |
| `0x51` | Called zero-initialized internal function |

To decode a custom error selector when you don't recognize it:

```bash
cast 4byte 0xf4d678b8   # -> "NotAllowed()" (one plausible match)
cast 4byte-decode "CustomError(address,uint256)" 0xf4d678b8000000...
```

Always check 4byte.directory — selectors collide and `cast` returns all candidates, pick by context.

## 6. Forking quirks and how to work around them

### 6.1 "block not found" on historical forks
Your RPC isn't archive. The challenge RPCs are all archive — but if you `vm.rollFork` too far back (> few days before the fork block) it may still fail. Stay within the fork's provided block window.

### 6.2 "nonce too low"
`forge script --broadcast` defaults to using the RPC-reported nonce. If a prior broadcast failed mid-way and left state behind, add `--skip-simulation` or manually set `--nonce N`.

### 6.3 Cached state stale
If a test that passed yesterday starts failing with "balance = 0 where 100 expected", your fork cache is out of date (the challenge staff may have reset the fork).

```bash
rm -rf challenges/<ch>/cache/ challenges/<ch>/.forge-cache/
forge clean
forge test ...
```

Also delete `~/.foundry/cache/rpc/<chain>/<block>/` if Foundry's global cache is poisoned.

### 6.4 "RPC method not found"
Some methods (`debug_traceCall`, `eth_createAccessList`) aren't exposed by all RPCs. If `-vvvv` traces fail, drop to `-vvv`. If the test itself uses `vm.rpc` to call a custom method, guard with `try/catch`.

### 6.5 Gas estimation off
Forked gas estimation can over- or under-shoot by 5-20%. In scripts use `--gas-estimate-multiplier 120` or hardcode `gas:` per tx.

### 6.6 `msg.sender` in scripts
Inside a `forge script` under `vm.startBroadcast(pk)`, every external call has `msg.sender = addressFromPk`. Pranks are IGNORED in broadcast mode. If you need a different `msg.sender`, that call must originate from a contract you deploy.

### 6.7 Time passing
`block.timestamp` in a fork test is fixed at the fork block. `vm.warp` adjusts it, but some protocols check `block.number` too. Use `vm.roll` in tandem when a cooldown depends on block height.

## 7. When you need to inspect storage directly

```solidity
// In a test
bytes32 raw = vm.load(someContract, bytes32(uint256(3)));  // slot 3
console.logBytes32(raw);

// Patch storage to set up a scenario
vm.store(someContract, bytes32(uint256(0)), bytes32(uint256(42)));
```

Or outside:

```bash
cast storage 0xContract 0x0 --rpc-url ch3
cast storage 0xContract --rpc-url ch3   # dumps contiguous slots (archive only)
```

Dynamic array slot math: for an array at slot `p`, element `i` is at `keccak256(p) + i`. Mapping `m[key]` at slot `p` is at `keccak256(abi.encode(key, p))`.
